# Saveable TTAS64 candidate — research, not deployment

This isolated candidate starts from the saveable full-float32 futex32 source and replaces only the async stripe mutex identity when `NT9_TTAS_MUTEX` is enabled. The 0/1 TTAS lock uses a CAS-acquire fast path, relaxed polling with PAUSE and a scheduler yield every 64 polls, and a release-store unlock. It has no futex waiters and cannot be mixed with futex state. Feature order, existing live atomic W/E/A reads and original stripe p are preserved. Float32 W/E/A and TC arithmetic are unchanged.

Safety/progress limitation: this lock is not fair or starvation-free; yield does not guarantee scheduling the owner. A preempted, stalled or stopped owner can indefinitely delay waiters, especially with 15 workers sharing 8 physical cores. Every trial must have a bounded timeout, own-process-only termination, RAM/cgroup/swap/disk guards, and an idle host. ThreadSanitizer and bounded contention tests do not prove all schedules or long-term progress. Its behavior during production shutdown, crash, and long training is not established.

Different concurrency specifications have different model hashes; the driver also requires exact source, binary and configuration identities. Futex32 checkpoints must be rejected, not relabeled or migrated. Tests must exercise real 1worker normal/16k archive, four logical fields, same-binary save/resume and rejection of old futex full/model-only identity. A 15worker run must verify pool provenance, 16k source_updates=1, checkpoint integrity and same-binary resume; it does not imply bit-identical multithreaded training or equivalent learning quality. Do not use for production or claim model quality until independent review and separate multi-seed longer quality evaluation.

The earlier no-save benchmark used a different spin8 futex control, fresh 15M/no archive, and reported 525,658→594,230 steps/s (+13.04%) on i06; that is not a throughput claim for this saveable implementation or its futex32 baseline. Intel recommends PAUSE and short spin loops and warns about spinlock progress: https://cdrdv2-public.intel.com/821612/248966-Optimization-Reference-Manual-V1-050.pdf and https://www.intel.com/content/www/us/en/developer/articles/technical/spin-locks-considered-harmful.html .

## Validation and 100M run preparation

Full9 source `76428313e6c6728559db14ee84225dca15b2c00cf29bec8103ca3b811e2db11c`; binary futex32 `f6b12b0bc296b90299a6c0463bab0420e2c10f937cc86ecfbd34270b69557e35`, TTAS `d04836898c652a7eb3213298aec399ea5b43c76befeff39b3213ecc80231eabd`, all-TU flags `BUILD9.json`. `tests/checks.log`: 15writer same-p and distinct-p/same-stripe, paused-owner/yield, stage24/overflow, same-TTAS native 4field bit-roundtrip and futex-model rejection. `tests/integration_ttas/RESULT.json`: 1worker real driver normal and 16k archive, four-field payload/episode/decision equal to futex32 and same-binary resume bit-exact; futex and prior full checkpoints rejected. `tests/online15/RESULT.json`: 3-digit 15worker real driver, actual manifest online archive, 5k checkpoint/replay, initial and resumed verified 16k donor source updates; no multithread equivalence claim.

`run100m.py` is a guarded 15worker seed7 full9 100M research run with the same donor manifest and online 500000/million request policy used by the earlier 100M adaptive/futex comparison. It adds an early 5k checkpoint/wave boundary absent from those older runs; this is a training-schedule difference and a quality-comparison confound. Same-binary 100M replay is not another training seed. Driver `wave_complete` timing excludes initial model initialization and checkpoint I/O, but includes archive and CSV activity inside each wave. Model SHA is independently rechecked with a direct guarded child, parent death, a timeout, and before/after file stat; `tests/guarded_sha_v3.log` covers timeout/parent death/mutation and wave delta arithmetic. Driver and its shell grandchildren run under a dedicated process-group watchdog, tested in `tests/watchdog_v2.log`; a killed or failed run is not reported as complete. The output report distinguishes donor-verified 16k from generated sources not independently verified.

The evaluation source `evaluate.cpp` is byte-identical to the prior adaptive/futex32 100M evaluator. `EVALUATION_BUILD.json` records matching TTAS identity/TU flags and evaluator hashes; `tests/eval_fixture/RESULT.json` compares a 3-digit equal-payload model against the existing futex evaluator for 20 seed-matched games, exact CSV and unchanged models. `evaluate_200.py` plans read-only evaluation of the initial 100M model only, with the existing seed 20261116 and 200 games and SHA-checked prior seed7 CSVs. Real 9-digit action-oracle and multi-training-seed quality equivalence are not established; a 200-game comparison of one model per variant is not a substitute for independent training seeds.

## Seed 7 research run and evaluation

The initial full9 15worker 100M wave completed at 100,071,069 steps; its step delta and raw wave timing are recorded exactly in `run_100m_seed7_i06_20261117/STATE.json`. The wave's reported 609,400 steps/s includes in-wave archive/CSV I/O and is not an all-I/O-excluded rate. Initial 16k source audit found 128 verified manifest donor uses and 58,399 normal starts; first and final checkpoint model SHAs passed independent checks.

The same-binary replay reached 100,076,985 steps and produced its final checkpoint, but the original runner stopped with **THP process-wide proxy below its 90% threshold**. The resumed peak proxy value and observation time were not persisted before the process exited; `madvise` success does not prove resident THP. Consequently the original two-phase run is **not PASS** and its speed cannot be treated as a controlled THP comparison. A separate read-only `postaudit_resume_s7_i06_20261117/RESULT.json` verified the saved final model SHA/identity and 114 manifest-backed 16k source updates plus 53,492 normal starts, without changing or overriding the original failed guard. THP may have affected performance, but no causal claim is possible without the missing measurement.

`eval_200_s7_i06_20261117/RESULT.json` is an evaluation-only PASS: initial 100M model SHA was unchanged before/after, with 200 games and evaluation seed 20261116. Mean/median/2048-or-higher: TTAS 27,780.70/10,512/60; existing adaptive seed7 12,059.44/9,858/18; existing futex32 seed7 36,683.78/16,180/89. Evaluation swapout increased 8 KiB within the guard. Different host, 5k early checkpoint boundary and non-deterministic 15worker trajectories confound this comparison; one training seed/model per variant cannot establish quality equivalence or a causal effect. The evaluation PASS does not change the original THP guard failure.
